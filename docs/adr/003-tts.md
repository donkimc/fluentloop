# ADR 003 — Use Kokoro for text-to-speech

- Status: accepted
- Date: 2026-10-12

## Context

Nightly generation needs speech for listening items and shadowing sentences.
The plan left the engine open: Kokoro (`kokoro-js`) or Piper in the worker
image. The worker is a Node container. The app's license is still unset, and
the product is meant to be a small paid service later, so a copyleft runtime
inside that image is a poor fit.

## Decision

Generate audio with Kokoro in the worker, through `kokoro-js`.

- Weights: `hexgrad/Kokoro-82M` v1.0, Apache-2.0.
- Runtime: `kokoro-js` 1.2.1, Apache-2.0. It runs ONNX in Node.
- Default voice: `af_heart`, graded A on the model card. `af_bella` (A-) is
  the backup.

Piper is out. `rhasspy/piper` is MIT, and it is archived. The maintained
line, `OHF-Voice/piper1-gpl`, is GPL-3.0. Each Piper voice also has its own
`MODEL_CARD` license, and some of those are restrictive.

## Consequences

- Phase 1 adds `kokoro-js` to the worker and uploads wav files to the Railway
  audio bucket. No Python and no extra system packages.
- This spike used the published license files and the model's own voice
  grades. It did not synthesize audio. Listen to `af_heart` on a few meetup
  sentences before the first set is published.
- Kokoro's card says the weights were trained on permissive audio, including
  a small amount of CC BY data (Koniwa, SIWIS) and synthetic audio from
  closed TTS models. The released weights are Apache-2.0, and the author
  allows commercial use.
